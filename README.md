# 局域快传 · LanDrop

> 同一个 WiFi 下，打开一个网页就能互传文件。扫码或输入 4 位识别码连接，支持**一传一**与**一传多**，实时显示传输速度与进度，文件全程只走本地局域网。

这是一个**零依赖**（只用 Node.js 内置模块）的局域网文件传输工具：你把它跑在自己的电脑上，手机 / 平板 / 另一台电脑连同一个 WiFi，扫码即可互传。没有云端、没有注册、没有广告。

```
┌──────────────┐       同一 WiFi / 路由器       ┌──────────────┐
│  电脑（服务端）│  ←──── 局域网直连 ────→  │  手机 / 平板  │
│  node server  │                              │   浏览器      │
└──────────────┘                              └──────────────┘
```

## 功能

| 能力 | 说明 |
| --- | --- |
| 扫码连接 | 会话页自动生成二维码，手机相机扫一下就进入，识别码自动填好 |
| 识别码连接 | 4 位数字识别码，跨设备手输即可加入 |
| 一传一 | 两台设备之间互传，双向同时传也支持 |
| 一传多 | 一个会话容纳多台设备，可发给「所有设备」或「仅某一台」 |
| 实时进度 | 上传 / 下载都有百分比、瞬时速度、剩余时间，SSE 推送无需刷新 |
| 送达回执 | 发送方能看到对方接收进度与「已送达 N 台」 |
| 大文件 | 流式读写磁盘，不占内存，实测可跑满千兆内网 |
| 断线恢复 | 刷新页面自动恢复会话与设备身份 |
| 自动清理 | 房间空置 10 分钟 / 空闲 6 小时自动删除文件 |

## 快速开始

需要 **Node.js 16 或更高版本**（无需 `npm install`，项目零依赖）。

```bash
# 1. 启动服务
node server.js
# 或指定端口 / 自动打开浏览器
node server.js --port 8080 --open

# 2. 电脑浏览器打开
#    http://localhost:5178
```

Windows 用户也可以直接双击 **`start.bat`**。

终端会打印手机可访问的局域网地址，并直接绘出二维码：

```
  本机访问   http://localhost:5178
  手机访问   http://192.168.1.23:5178   (需在同一个 WiFi)

  ██████████████  ████  ██    ██████
  ██          ██  ████      ██    ██
  ...
```

### 三步传文件

1. 电脑打开页面 → 点「新建会话」→ 得到 4 位识别码 + 二维码。
2. 手机连同一个 WiFi，相机扫码（或打开地址手输识别码）→ 自动加入会话。
3. 在电脑上选择文件 / 拖进去 → 手机点「接收」，或勾选「自动接收」。

## 一传多怎么用

一个会话里的**每台设备都可以发文件**，不只是房主。

- 发送区右侧的「发送给」下拉框：默认 `会话内所有设备`，也可以只发给某一台。
- 接收方会在列表里看到文件，可逐个「接收」，或点「全部接收」。
- 发送方文件旁的「已送达 N 台」会随接收情况实时更新。

## 实现说明

**为什么不用 WebRTC？**
WebRTC 的 P2P 需要公网信令服务器，跨网时还常走 TURN 中转，且浏览器内存扛不住超大文件。本项目改由**你本机的 Node 服务**做局域网内中转：文件从发送设备经路由器到你本机磁盘，再由本机流给接收设备 —— 全程不出内网，速度取决于局域网带宽，而且天然支持一传多（一份文件多个接收方同时下载）。

**传输链路**

- 会话：`POST /api/room/create` 生成 4 位码；`POST /api/room/join` 加入；SSE `GET /api/events` 推送设备列表与进度。
- 上传：`POST /api/upload` 原始字节流直接写入磁盘，边收边广播进度（仅通知目标设备）。
- 下载：`GET /api/download/:id` 支持 Range，服务端按实际写出字节数计算速度并回推给收发双方。
- 清理：房间无人 10 分钟或空闲 6 小时自动删文件；「退出会话」立即清理。

**接口一览**

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/info` | 本机网卡 / 端口信息 |
| POST | `/api/room/create` | 新建会话，返回识别码 |
| POST | `/api/room/join` | 用识别码加入 |
| GET | `/api/room/state` | 拉取房间状态（刷新恢复用） |
| GET | `/api/events` | SSE：设备列表、上传/下载进度 |
| POST | `/api/upload` | 上传（`name`、`size`、`target=all\|id`） |
| GET | `/api/download/:id` | 下载（支持 Range） |
| POST | `/api/file/remove` | 发送方删除文件 |
| POST | `/api/leave` | 退出会话 |

## 常见问题

**手机打不开页面？**
1. 确认两台设备连的是同一个 WiFi（手机不要开流量）。
2. Windows 首次运行会弹「防火墙」提示，必须允许**专用网络**访问，否则手机连不进来。若已误点拒绝：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 勾选 Node.js。
3. 公司 / 学校 WiFi 常开「AP 隔离」，设备之间不能互访，此时改用手机热点。
4. 若电脑有多个网卡，会话页二维码下方的「地址」下拉可切换 IP。

**扫码没反应？**
用手机系统相机扫码（微信扫码也能识别链接）。扫码后识别码会自动填入并直接加入。

**下载的文件在哪？**
浏览器默认下载目录。手机上通常在「文件 / 下载」里，iOS Safari 会先弹预览再存到「文件」。

**速度慢？**
瓶颈通常是 WiFi：2.4G 频段一般 5–10 MB/s，5G 频段 40–100 MB/s，有线千兆可到 110 MB/s。手机与路由器之间的信号强度影响最大。

**能传多大文件？**
服务端不限制（保护上限 200GB），流式落盘不占内存。接收端用浏览器下载，超大文件请确保设备剩余空间足够。

**和 GitHub Pages 有关系吗？**
GitHub Pages 只能托管静态文件，无法运行本项目的 Node 服务，所以**本项目代码托管在 GitHub，运行时在本机执行 `node server.js`**，而不是部署到 Pages。这也是「文件走本地局域网」的前提。

## 安全提示

- 4 位识别码在局域网内可被枚举，**只建议在家庭 / 办公等可信网络使用**；用完点「退出会话」。
- 服务监听 `0.0.0.0`，同一局域网内拿到地址与识别码的人都能加入。
- 文件保存在本机 `uploads/` 目录，房间销毁即删除；退出时按 `Ctrl+C` 停止服务。
- 上线公网请自行加反向代理与鉴权，本项目未内置账号体系。
