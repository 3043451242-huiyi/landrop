# 局域快传 · LanDrop

> 同一个 WiFi 下，打开一个网页就能互传文件。**纯静态网页**，扫码或输入 4 位识别码即可连接，支持**一传一**与**一传多**，实时显示速度与进度，文件通过 WebRTC 点对点直连，**不经过任何服务器**。

```
   电脑（浏览器）  ═══════ WebRTC DataChannel 直连 ═══════  手机（浏览器）
        │                                                  │
        └── ① 配对握手（MQTT 公共信令，几百字节，走公网）──┘
             ② 文件数据（走局域网，跑到路由器带宽上限）
```

- **不用装任何程序**，不用在本机跑服务，也不用把网页文件拷给别的设备
- **不用上传云端**：配对阶段只有一行 SDP 文本经过公共信令服务器，文件内容始终在两台设备之间流动
- 仓库本身是纯静态文件：`index.html` / `app.js` / `styles.css` / `vendor/`，可直接扔到 GitHub Pages

## 功能

| 能力 | 说明 |
| --- | --- |
| 扫码连接 | 会话页实时生成二维码，手机相机扫一下即进入，识别码自动填好 |
| 4 位识别码 | 手输/粘贴自动加入，识别码错误有防爆破限流 |
| 一传一 | 任意两台设备互传，双向同时传也支持 |
| 一传多 | 一个会话容纳多台设备，房主可「发给所有设备」或「仅某一台」 |
| 智能提速 | 起步 16KB 小包 + 256KB 缓冲**慢速试连**，通道确认通了自动升到 128KB 包 + 16MB 缓冲 |
| 实时进度 | 收发双向显示百分比、瞬时速度、剩余时间、已送达台数 |
| 离线兜底 | 信令服务器不可用时，用「手动配对」两段文本完成握手，全离线可用 |
| 通道可见 | 实时显示「局域网直连 / P2P 直连 / 中继 / 已断开」 |

## 快速开始

### 方式一：GitHub Pages 静态托管（推荐，所有人打开同一个网址）

1. 新建仓库（建议名 `landrop`），把本仓库内容推上去；
2. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，分支 `main`、目录选 `/ (root)`；
3. 等 1~2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。

把这个网址发给同事/家人，手机扫码就能传文件，**不需要给对方发任何文件、也不需要装任何东西**。

### 方式二：本地静态预览

任意静态服务器都可以：

```bash
npx serve .            # 或 python -m http.server 8080
```

> 直接双击 `index.html` 用 `file://` 打开会因浏览器安全策略无法建立 WebRTC 连接，请用 http 访问。

### 方式三：本机中转模式（可选，超大文件更省内存）

仓库里保留了一个零依赖 Node 服务，走「本机中转」，适合 10GB 以上文件、或手机浏览器内存吃紧时：

```bash
node server-mode/server.js --open      # 或双击 server-mode/start.bat
```

## 使用流程

1. 一方打开网页 → 点「新建会话」→ 得到 4 位识别码 + 二维码；
2. 另一方连同一个 WiFi，相机扫码（或打开网址手输识别码）→ 自动加入；
3. 通道建立（几秒内，状态从「连接中」变「局域网直连」）；
4. 选择文件发送 / 接收方点「保存」，或勾选「自动保存」直接落盘。

## 一传多怎么用

- 会话里的**每台设备都可以发文件**；
- 发送区「发送给」下拉：房主可选 `会话内所有设备` 或 `仅某台设备`；加入方默认发给房主；
- 发送方文件旁显示「已送达 N/M 台」，接收方能看到对方接收进度。

## 实现要点

**信令 vs 数据面**

| 阶段 | 通道 | 流量 | 说明 |
| --- | --- | --- | --- |
| 配对握手 | MQTT over WSS（公共 broker） | 几百字节 | 只传 SDP 与 ICE 候选，1 秒内完成 |
| 文件传输 | WebRTC DataChannel | 全部字节 | 同一局域网内走 host 候选，点对点直连 |

信令不可用时，页面会提示并展开「手动配对」：一方生成邀请码文本发给对方，对方粘贴后生成应答码回传，第三次粘贴即可连通 —— 这条路径完全不需要公网。

**慢启动 → 高速**

WebRTC 直接开大包大缓冲，一旦链路不稳就会浪费带宽重传。发送端因此采用渐进策略：

```
起步      16KB 分包 / 256KB 缓冲    ← 先确认通道真的通了
> 256KB   64KB 分包 / 1MB 缓冲
> 1MB    128KB 分包 / 16MB 缓冲    ← 切换为当前的全速模式
```

界面上的「试连 / 极速」标签会实时显示当前档位。

**为什么是「局域网直连」而不是绕服务器**

ICE 只收集到 `host` 候选时，同一 WiFi 的两台设备直接互连，不经过任何第三方中转；配置里没有 TURN，因此**跨网段时连接会失败，而不是悄悄走公网中转**——这也保证了「文件不出局域网」。

**信令用的公共 broker**

- `wss://broker.emqx.io:8084/mqtt`（默认），备选 `wss://broker.hivemq.com:8884/mqtt`
- MQTT 客户端是自己实现的 `vendor/mqtt-lite.js`（约 200 行，无第三方依赖），只用了 CONNECT/SUBSCRIBE/PUBLISH/PING
- 信令主题为 `landrop/v2/<4位码>`，里面只有握手信息，**不含文件名与文件内容**

## 常见问题

**手机打不开 / 连不上？**
1. 两台设备必须连**同一个 WiFi**（手机别用流量）；
2. 公共 WiFi 常开「AP 隔离」，会阻止设备互访 —— 换手机热点试试；
3. 信令需要能连上 `broker.emqx.io:8084`；被墙时用「手动配对」，完全离线可用；
4. GitHub Pages 在国内可能访问较慢，可把仓库同步到 Gitee / Cloudflare Pages 等静态托管。

**扫码没反应？**
用手机系统相机扫码（微信扫一扫也能识别链接），扫码后识别码会自动填入并直接加入。

**传大文件会不会把手机内存撑爆？**
接收端先收齐分片再组装成 Blob，1GB 以内没问题；超大文件建议用「本机中转模式」在电脑上收发。

**速度上不去？**
瓶颈在 WiFi：2.4G 频段约 5~10 MB/s，5G 频段 40~100 MB/s，有线千兆可到 110 MB/s。

**和 GitHub Pages 什么关系？**
Pages 只负责托管网页；文件传输发生在浏览器与浏览器之间（WebRTC），与托管在哪无关。

## 安全提示

- 4 位识别码在公网信令上是可枚举的：他人若猜到码并抢先加入，能看到你发的文件。**请在可信网络使用**，或改用「手动配对」（随机邀请码不可枚举）。
- 文件内容是端到端加密的（WebRTC 内置 DTLS），中间人看不到明文。
- 本项目未做身份认证，只适合个人/内网使用；对外服务请自行加鉴权与限流。
